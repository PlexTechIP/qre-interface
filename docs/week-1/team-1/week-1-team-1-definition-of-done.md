# Week 1 — Team 1 (Sun Min + Emma) — Definition of Done

The bar for the Tue Jul 7 checkpoint.

## Functional

- [ ] Figma file contains high-fidelity screens for all four surfaces: Run
      Configuration, Results Area, Run History Area, Comparison page
- [ ] Run Configuration shows all five inputs: application, architecture,
      error correction + factory, error budget, QRE version
- [ ] Results Area shows the five core metrics, metric filtering,
      additional-metrics access, and configuration summary
- [ ] Run History supports view, delete, duplicate, and select-for-comparison
- [ ] Comparison page includes a runs × metrics table, at least one metric
      visualization, and labels for configuration differences
- [ ] Loading/running, empty, and error states are represented
- [ ] Google Doc requirements are satisfied or listed as open questions in
      presenter notes

## Quality

- [ ] Screens are high fidelity: real layout, type, color, spacing, and
      realistic QRE data
- [ ] Desktop framing is clear (about 1280×800 or larger) with a consistent
      visual direction
- [ ] Screens are named and ordered Configure → Results → History → Compare
- [ ] Week-2 implementers can tell what to build without guessing

## Process

- [ ] Both teammates have verified repo access and read the mockup-spec Google
      Doc
- [ ] Figma link posted in the project channel with view access verified
- [ ] Presenter-notes frame includes 2–3 key design decisions and open
      questions
- [ ] Walkthrough prepared for the checkpoint
- [ ] Checklist and definition-of-done files committed with boxes checked

## Explicitly NOT required

- Code, React components, Electron scaffold, engine spike, persistence/export
  implementation, or polished Figma prototype interactions
